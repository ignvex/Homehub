# v1.1.0

HomeHub 作为宿主接入 HomeHub Extension 的签名通道。这是**纯新增**版本：
未配置时行为与 1.0 完全一致，已有的 REST 端点、数据库结构与权限模型一律不动。

> 这条通道目前是**实验性**的：对端 HomeHub Extension 仍处于 alpha，其 API
> 契约可能在 1.0 正式版前微调。默认关闭，建议先在联调环境跑通再上生产。

> **配置字段已变。** 本文记录的是 v1.1.0 当时的写法：私钥用
> `extension_hub.private_key_path`，对端公钥用 `auth.hub.public_key_path`。
> 后续版本已改为把密钥内容直接写进 `extension.private_key_pem` 与
> `auth.hub.public_key`，不再读文件。照着本文改配置会启动失败，以
> [extension-hub.md](../extension-hub.md) 与
> [hub-integration.md](../hub-integration.md) 为准。

## 亮点

- **请求签名通道**：宿主持一把 Ed25519 私钥，Extension 侧保存公钥。身份不是
  某个字段，而是签名本身——`/api/v1/hub/*` 不接受 Bearer。
- **订阅镜像**：把本地 `rss_feeds` 推到 Extension，让它拥有一份独立抓取、
  媒体全量本地化的阅读器。只推不删，删除必须逐条确认。
- **访问密钥**：宿主为使用者签发 Extension 登录凭证。明文只在签发响应里
  出现一次，Extension 侧只存 `sha256`。
- **四层状态探测**：配置 / 网络 / 签名 / 模块分别回答，排障时不用猜。

## 升级

不需要迁移，也不需要修改现有配置。`extension_hub` 段缺失即视为关闭。

```bash
go build ./...
pnpm --dir web build
```

要启用对接，先准备密钥：

```bash
openssl genpkey -algorithm ed25519 -out extension-hub.key
openssl pkey -in extension-hub.key -pubout -out extension-hub.pub
chmod 600 extension-hub.key
```

把公钥放到 Extension 主机的 `/etc/hhe/homehub.pub`，然后在 `config.json` 里：

```json
{
  "extension_hub": {
    "enabled": true,
    "base_url": "https://ext.example.com/api/v1",
    "private_key_path": "/etc/homehub/extension-hub.key"
  }
}
```

`base_url` 必须带 `/api/v1`，配置校验会拒绝缺前缀的写法。保存后热重载生效，
不需要重启。

## 新增端点

| 方法 | 路径 | 最低权限 |
| --- | --- | --- |
| `GET` | `/api/v1/extension/status` | 登录 |
| `GET` | `/api/v1/extension/subscriptions` | 登录 |
| `POST` | `/api/v1/extension/subscriptions` | 3 级 |
| `POST` | `/api/v1/extension/subscriptions/sync` | 3 级 |
| `DELETE` | `/api/v1/extension/subscriptions/{id}` | 2 级 |
| `GET` / `POST` | `/api/v1/extension/keys` | 2 级 |
| `DELETE` | `/api/v1/extension/keys/{id}` | 2 级 |

界面在「系统管理 → Extension 对接」，仅管理员可见。

## 契约

`internal/hubclient` 在 1.0.0 就已经实现且从未被调用；本版补上调用方。
签名域前缀仍为 `homehubext/req/v1`，协议端点未变。

几处刻意不透传上游状态码：Extension 的 401 折成 HomeHub 的 502，避免前端把
「宿主签名不对」误认成「自己掉登录」并踢回登录页。详见
[docs/extension-hub.md](../extension-hub.md)。

## 验证

```bash
go build ./... && go vet ./... && go test ./...
pnpm --dir web lint && pnpm --dir web build
```

新测试覆盖：间隔格式化、订阅字段的三态映射、四层状态判定、签名端到端验签

## 已知限制

- **没有和真实的 Extension 实例联调过**。协议实现以固定测试向量与本地
  假服务端验证，真实环境下的时钟偏差、nonce 去重表容量、限流阈值未实测。
- 订阅删除不联动：本地删了订阅源，Extension 侧不会自动跟进，需要在
  「Extension 对接」页逐条移除。
- 不支持 OPML 导入导出——对端尚未实现（M10）。
- 宿主公钥同一时间只支持一把，轮换期间旧签名会短暂 401。HomeHub 这边同名
  覆盖私钥文件即会重新读取（按 `mtime` + 大小判定），不需要重启；但
  Extension 侧读公钥只在启动时，所以换公钥仍需重启它。
